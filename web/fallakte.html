A record is a verdict and a case file is a workspace. A Nordstern record says where a disease stands, rated on a date, signed, and append-only so that a citation keeps resolving. It is meant to be hard to change. A case file is the opposite: notes that grow weekly, models that turn out to be wrong, a dated log of corrections, and a list of things a stranger could pick up. Most diseases will never have one. A case file exists where work has started, which makes this list the short one.

howWhat a case file holds

Eleven sections, in the order a stranger needs them. The one that does the work is the mechanism, step by step: a numbered chain, one row per step, each marked established, partial or open, with the model that shows it. An empty model column is left empty, because that is the list of things worth building. Two further rules earn their place: every model states what it refuses to claim, and a section called what we got wrong is dated and never edited away.

The template, and the rule that cost the most to learn
Fallakte points at Nordstern and at Engpass, and neither knows it exists — Fallakte/test_boundary.py asserts that rather than trusting it, including that no disease record carries a pointer back. A record is append-only and citable; a case file changes every week, and a pointer from the first to the second would make the verdict as unstable as the workspace.

The spine and the prose are kept apart and the split is enforced. case.yaml holds ids, links, paths, dates and statuses — what a checker can verify. The case file itself is markdown. check.py rejects prose in the spine, and fails if a question id or a model path in the spine is never discussed in the prose: a question with a status and no text is a number, not a question.
